# Calorie shadow recorder integration

Existing shadow validator on main had no capture/export call site, filtered missing HR before adjacent integration, trapped on empty valid samples, and described 3-second clipping as rejection. This batch corrects only diagnostics; no calorie, sleep, strain, steps, HRV, recovery, history or restore algorithms are replaced.

For new recorded workouts, retain actual accepted HR receipt timestamps with fractional seconds and explicit continuity segment IDs. A pause, disconnect, invalid reading or existing interval break ends continuity. Save an independent protected JSON sidecar after successful ordinary workout save; delete sidecar when its workout is deleted. Existing persisted workout records are not rewritten. Diagnostic ZIP contains calorie-shadow/<UUID>.json with source observations, profile/HR anchors, activity classification, pauses, saved active calories and per-model coverage/energy. Full restorable backups exclude the sidecar. No cloud upload. Cap 100,000 samples, fail closed on changed/missing anchors, out-of-order data or truncation.

Production comparator mirrors recorded-workout 30-second rejection and gated above-basal rate. Gross = basal for covered intervals + active; recovered clips unmarked gaps to 3 seconds but never bridges explicit breaks. The recovered net is separately labeled, not claimed to be WHOOP active; the experiment assumes max-HR reference and sex-to-baseline mapping. Different coverage means totals cannot be treated as equal-duration accuracy. Measured cadence/MET fallback remains unchanged in production; validator can expose a separate walking cadence estimate when supplied with measured steps, but recorder currently has no reliable workout-total step count so no invented fallback. Running, treadmill, walking, strength and other classes stay distinct. Real matching WHOOP reference and held-out waveform evidence still required; no production migration authorized.

Native CI pending. Synthetic tests cover fractional time, pause, invalid/missing HR, duplicate conflicts, gap policies, profile change, JSON round-trip and diagnostics-only archive. The recorder captures received HR observations rather than raw PPG/beat waveforms.
